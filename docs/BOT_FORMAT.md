# Future bot format — contract v1

## 1. Required files

Every bot lives under `bots/<bot_id>/`. The directory name and manifest `id` must match. Use letters, digits, underscores, or hyphens. Nothing is registered inside the simulator source.

```text
bots/my_bot/
  bot.json
  adapter.py
  code/
    __init__.py
    strategy.py
    models/          # Optional local models; never fetched during a match
```

`python -m simulation new-bot my_bot` creates the template. `code/` is your implementation; `adapter.py` translates the public interface to your implementation and translates its return value back. For a native bot that translation can be a one-line delegation.

### bot.json

```json
{
  "schema_version": 1,
  "id": "my_bot",
  "name": "My local policy",
  "runtime": "python",
  "entrypoint": "adapter:Bot",
  "capabilities": {"variant": "nlhe", "min_players": 2, "max_players": 9},
  "default_params": {"max_call": 40},
  "runtime_network": false,
  "competition_eligible": false
}
```

`min_players` must be 2 in this engine: table knockouts and tie-breaks can produce heads-up play. `max_players` is a hard admission limit. Do not declare multi-player support for an algorithm that only handles heads-up. Eligibility and runtime-network fields are declarations, not security enforcement or an organizer’s certification. Unknown metadata may be retained, but configuration fields used by the engine are validated separately.

### adapter.py

```python
from simulation.sdk import BaseBot, Action, Observation
from .code.strategy import decide

class Bot(BaseBot):
    def act(self, obs: Observation) -> Action:
        return decide(obs, self.config, self.rng)
```

### code/strategy.py

```python
from simulation.sdk import Action, Observation

def decide(obs: Observation, config: dict, rng) -> Action:
    legal = obs.legal_actions
    if "check" in legal.types:
        return Action("check")
    if "call" in legal.types and legal.call_amount <= config.get("max_call", 40):
        return Action("call")
    return Action("fold")
```

Always use relative imports for files inside the bot, such as `.code.strategy`. Shared utilities may be imported from `utils`. Do not import `simulation.engine` inside a submission or read results/deck files. The supplied Docker SDK image does not include the engine.

## 2. Required input: Observation

`act(obs)` receives an immutable, player-specific snapshot. Exact definitions are in `simulation/contracts.py`; `examples/observation.json` is an actual serialized input generated by the engine. The same JSON shape is used for command-language bots.

| Field | Type / meaning |
|---|---|
| `schema_version` | Integer `1`; reject incompatible versions |
| `game_id`, `hand_id` | Strings identifying the current game and hand |
| `hand_number` | One-based hand count within the game |
| `hero_seat` | Zero-based index of this bot; the bot is the actor when `act` is called |
| `button_seat`, `small_blind_seat`, `big_blind_seat` | Stable table seat indices |
| `street` | `preflop`, `flop`, `turn`, or `river` |
| `hole_cards` | Exactly two private rank+suit strings, e.g. `("As", "Td")` |
| `board` | Zero, three, four, or five public cards |
| `players` | All table slots, including folded/all-in/busted slots; see below |
| `pot` | Total chips contributed so far, including outstanding wagers |
| `pots` | Provisional contribution layers with eligible seats; settlement can refund unmatched chips |
| `legal_actions` | Legal types, call price, and raise bounds; see below |
| `history` | Ordered public events from this hand, including blinds/antes/actions/board/refunds |
| `small_blind`, `big_blind`, `ante` | Current hand’s rules, integer chips |
| `action_timeout_ms` | Decision time budget |
| `hands_remaining` | Number of scheduled hands after the current hand, before the cap |

Each `players` item contains `seat`, `player_id`, `stack` (uncommitted chips), `starting_stack` (at this hand’s start), `street_bet`, `total_contribution` (all streets and antes in this hand), and `status` (`active`, `folded`, `all_in`, or `out`). Seats never collapse/reindex when somebody busts. No player item contains another player’s private cards.

Python-only convenience properties are `obs.hero`, `obs.opponents` (other active/all-in players), and `obs.to_call` (uncapped price). They are not extra JSON fields.

Card ranks are `23456789TJQKA`; suits are `cdhs`. There is no `10s`, numeric card ID, suit-first encoding, or joker at this boundary.

The snapshot deliberately excludes the remaining deck, burn cards, unseen opponent cards, game-engine object, dealer random generator, master seed, and future board. The player’s own RNG seed is supplied at initialization, from a separate stream.

## 3. Legal actions and output

`legal_actions` contains:

```json
{
  "types": ["fold", "call", "raise"],
  "to_call": 10,
  "call_amount": 10,
  "min_raise_to": 40,
  "max_raise_to": 2000,
  "full_min_raise_to": 40,
  "short_all_in_only": false
}
```

`to_call` is the uncapped amount needed to match the table wager. `call_amount` is the amount the hero can actually pay, capped by the remaining stack. Use `call_amount` for an all-in call’s price.

`min_raise_to` and `max_raise_to` bound the **hero’s total current-street contribution after raising**. They are `null` when raising is not legal. When only an under-minimum all-in raise is possible, both bounds equal the all-in total, `short_all_in_only` is true, and `full_min_raise_to` preserves the usual full-raise target above the hero’s stack.

There are exactly four canonical output types:

```python
Action("fold")
Action("check")
Action("call")
Action("raise", raise_to=120)
```

Equivalent JSON:

```json
{"type": "raise", "raise_to": 120}
```

A bet into an unopened street is also `raise`. There is no separate canonical `bet` or `all_in`. Check/call/fold carry no sizing field. Unknown fields, unknown types, fractional chips, booleans used as integers, negative amounts, and out-of-bounds raises are errors.

**Example:** you have already contributed 30 this street; the current table wager is 80. `Action("raise", 200)` pays **170 new chips**, of which 50 completes the call and 120 is the raise increment. It does not pay 200 new chips. Earlier-street contributions do not enter this calculation.

The engine never silently changes a canonical native action. A legacy adapter may explicitly round/clamp its own upstream output; those corrections increment `adapter_repairs` and are separate from bot failures. A conversion from a deliberately merged check/call protocol is not itself a repair.

## 4. Lifecycle and stateful bots

The lifecycle is:

```text
construct Bot(config, seed)                  once per competitor per game
on_game_start(GameContext)                  once per game
  on_hand_start(Observation)                for each hand in which the seat has chips
  on_event(Event)                           public events as they occur
  act(Observation) -> Action                whenever this bot must act
  on_event(Event)                           includes the bot’s own accepted action
  ...
  on_hand_end(HandResult)                   all seated bots, including folded/busted
on_game_end(dict)                           final game stacks and statistics
close()                                    cleanup hook; make it idempotent
```

All hooks except `act` are optional because `BaseBot` provides no-ops. `close()` is best-effort; a timeout/forced process termination cannot guarantee cleanup.

`on_hand_start` can have an empty legal-action list when another player acts first or the hand immediately runs out after all-in blinds. Use that hook for initialization, not for returning an action.

`history` in snapshots is a complete per-hand record; `on_event` delivers the same public events incrementally. **Do not apply both twice.** An opponent modeller should either rebuild from `obs.history` or keep a per-hand `last_sequence` and ignore already-seen sequence numbers. Initial blinds/antes are present in the hand-start snapshot and then published through events. Reset deduplication at hand start.

An event has `sequence`, `type`, `street`, optional `seat`, optional `action`, `paid`, optional `raise_to`, and `cards` for public board deals. Types are `blind`, `ante`, `action`, `board`, and `refund`. For an action, `paid` means new chips paid now; `raise_to` has the canonical meaning above. Refund amounts are positive refunded chips. No event includes secret deal order.

Store ranges, opponent statistics, recurrent-network state, and caches on `self`. They persist across hands **within a game**. By design each new seat-rotation game and each tie-break leg creates fresh bot instances; default memory does not carry between games, opponents’ private contexts, or tournament iterations. Training/offline persistence must be an explicit build-time process, not uncontrolled file writes in the no-network runtime.

`HandResult` provides final public board, per-seat hand-start/final stacks, payoffs, settlement pots, public history, and shown cards. It exposes cards of all nonfolded players at showdown under this project’s auto-show profile; folded/uncontested-winning private hands stay hidden. It is not the private replay record.

`GameContext` provides player IDs/seat, initial game stacks, blind settings, hand cap, and game ID. `on_game_end` receives stacks and recorded failure/counter statistics.

## 5. Independent instances and randomness

Put one implementation in one bot folder. Enter it more than once by using distinct competitor IDs:

```json
[
  {"id": "tight_v1", "bot": "my_bot", "params": {"max_call": 20}},
  {"id": "loose_v1", "bot": "my_bot", "params": {"max_call": 80}}
]
```

Manifest defaults are merged with entry parameters; the latter win. `self.rng` is the bot’s seeded `random.Random`. Use it rather than wall-clock time. The subprocess worker also seeds global Python/NumPy randomness for legacy policies. Cross-platform numeric/library changes can still affect decisions; reproducibility assumes fixed code, parameters, dependency versions, and runtime profile.

In-process mode is for trusted sequential testing only. It restores Python/NumPy global RNG state but cannot isolate arbitrary globals, files, imports, threads, or malicious code. Subprocess/Docker is the per-instance boundary.

## 6. Non-Python bots: JSON Lines command protocol

Manifest example:

```json
{
  "schema_version": 1,
  "id": "cpp_policy",
  "name": "C++ policy",
  "runtime": "command",
  "command": ["{bot_dir}/code/bot"],
  "docker_command": ["/opt/arena-bin/cpp_policy"],
  "capabilities": {"variant": "nlhe", "min_players": 2, "max_players": 9},
  "default_params": {},
  "runtime_network": false,
  "competition_eligible": false
}
```

Compile the executable before a match. No shell interpolation is performed; `command` is an argument array, with only `{bot_dir}` substitution. For Docker, bake the executable into the image and declare its `docker_command`. The supplied PokerForBots Go bridge is a running example of this format.

The parent writes exactly one JSON object plus newline per request. The child must flush exactly one corresponding response line. Write diagnostics to **stderr**, never stdout.

```json
{"request_id": 1, "method": "initialize", "data": {"seed": 123, "params": {}}}
{"request_id": 1, "ok": true}
```

```json
{"request_id": 2, "method": "act", "data": {"schema_version": 1, "...": "complete Observation"}}
{"request_id": 2, "action": {"type": "call"}, "telemetry": {"upstream_calls": 1, "adapter_repairs": 0}}
```

The illustrative `...` above is not a valid observation field; use `examples/observation.json` for a complete payload. Every lifecycle hook uses the same `{request_id, method, data}` envelope and responds with `{request_id, ok: true}`. Errors may return `{request_id, error: "message"}`. Missing/mismatched request IDs and malformed/oversized responses are failures. Limits are 8 MiB/request and 1 MiB/response. The same deadline covers writing the request and receiving the response.

Counters are diagnostic self-reports, not trusted competition scores. The engine validates every selected action and computes all chips/points itself.

## 7. Admission and testing checklist

Run `python -m simulation validate-bot --bot my_bot --hands 50`. Then run the test suite and repeated tournaments across several seeds/seat positions. Validate custom parameters in your constructor, declare the truthful table-size cap, keep external requirements/model artifacts local, and use the Docker profile before accepting untrusted submissions. A successful import or one successful action is not proof of strategic strength or compatibility with every legal state.

The v1 arena rejects manifests declaring `runtime_network: true`; a declaration of `false` is admission metadata, not proof that arbitrary bot code cannot open a network connection. Use the Docker runner for isolation.
